## 3. Findings

### 3.1 Broken `../img/` references (HIGH — site-wide)
All 21 HTML pages load the three header logos via `../img/...`
(`A-PASOS-DE-GIGANTE_BLANCO.png`, `LOGOTIPO-PRINCIPAL-BLANCO.png`,
`WEQ.png`); `index.html` additionally loads `../img/Economía_Portada.png`.
**64 occurrences total.** There is **no `img/` directory at the `../`
level** — the only image directory is `Secretaría de Economía/img/`
(i.e. `./img/`). Every one of these references is therefore broken in
this snapshot; the correct relative path would be `img/` (same
directory). Full per-line table in `PATH_AUDIT.md`. *Not fixed in Phase
0 by instruction.*

> Hypothesis: the production server may host the site with a different
> directory layout where `img/` sits one level above the pages. To be
> confirmed once the deployment owner is identified (tracked as an Open
> Question in CLAUDE.md).

**only the ABR26** versions of the five regional profiles, in Spanish

but are referenced by **no HTML page** (verified: zero matches for
`ENE2026` / `CENTRO -DESIERTO 2026` across all pages). These 10 files

### 3.4 Markup defects in `index.html` (MEDIUM — likely repo-wide)
- **Line 15:** malformed Font Awesome 4.7 link uses a Spanish element
  name and smart/curly quotes:
  `<enlace rel="hoja de estilo" href="…font-awesome…"></enlace>` — not
  valid HTML; the stylesheet does not load. A separate Font Awesome kit
  is also loaded (line 16), so two icon systems are half-wired.
- **Line 10:** empty prefetch — `<link rel="prefetch" href="" as="document">`
  (prefetches the current document).
- **Lines 41–48:** every nav link carries
  `class="navegacion__enlace navegacion__enlace--activo""` — a stray
  trailing double-quote and the *active* modifier applied to **all**
  links, so no single page is correctly highlighted.

These patterns appear in the shared header/nav block and are expected to
recur across the other 20 pages (to be confirmed page-by-page in a later
phase).
